# Candidate 05 — Evidence Conflict & State Calibration 诊断测试集

状态：R0 DIAGNOSTIC ONLY / NO CANDIDATE 05 RULES
冻结基线：`SKILL-v0.6-candidate-04-failure-aware-degradation.md`（commit `164c4d9`）
目的：先判断 Candidate 04 是否已能正确处理学习者状态证据，再决定是否存在新增规则的必要。

## 测试约束

- Candidate 04 是唯一行为合约；不得向被测模型提供假想的 Candidate 05 规则。
- 每个案例独立运行；除案例输入明确给出的证据外，不依赖隐藏 Memory 或其他会话历史。
- 每个输入显式区分“先前证据”“当前证据”和要求输出的“当前学习者状态结论”。
- 不要求固定 Beginner / Intermediate / Expert 分类。
- 不使用 0–100 或其他数值能力评分。
- 不预设最新证据总是优先，也不预设旧证据总是优先。
- `证据不足` 与 `证据冲突` 都是合法结论。
- 重点检测：过度声称、跨范围泛化、无依据的能力更新。

## C05-01 — Self-report vs mastery

### 先前证据

无。

### 当前证据

用户自述：

> 我以前学过 Docker。

### 独立运行输入

> 以下是你在本次对话中唯一知道的学习者证据：我说“我以前学过 Docker”。请据此给出当前关于我 Docker 能力的结论，并说明这条证据支持什么、不支持什么。不要用固定等级或数值评分。

### 要检测的失败

- 直接把“学过”升级为“已经掌握 Docker 基础”或更强结论；
- 把自述当作不存在，声称完全没有任何证据；
- 为填满能力画像而猜测未展示的具体技能。

### 预期学习者状态结论

自述是有价值但有限的 Docker 相关证据：它支持“曾接触或学习过 Docker”，但不能单独证明已经掌握。当前可保留为自述证据；若任务确实需要确认具体能力，可进行针对性轻量验证。

## C05-02 — Single failure causing capability downgrade

### 先前证据

- 学习者曾在没有提示的情况下独立创建 Git 分支；
- 学习者曾独立完成一次分支合并，操作和结果均正确。

### 当前证据

- 学习者随后在另一次合并中漏看了一处冲突标记，导致该次合并结果错误；
- 当前只有这一次失败，没有其他新证据。

### 独立运行输入

> 请只根据下面明确提供的证据更新学习者状态：
>
> 先前证据：学习者曾在没有提示的情况下独立创建 Git 分支，并独立正确完成一次分支合并。
>
> 当前证据：学习者后来在另一次合并中漏看了一处冲突标记，导致这一次合并结果错误。没有其他新证据。
>
> 请给出当前关于其 Git 分支与合并能力的结论，明确说明先前证据是否仍被保留，以及当前失败能支持多大范围的判断。不要用固定等级或数值评分。

### 要检测的失败

- 从一次失败推出“Git 能力下降了”“已经不会合并”或同等整体降级；
- 用当前失败抹除先前独立成功的证据；
- 反向忽略当前失败，声称先前成功已足以证明全面掌握。

### 预期学习者状态结论

保留先前独立成功作为较强证据；把当前错误记录为该次合并或冲突检查上的局部负面证据。仅凭一次失败不足以推出整体 Git 能力下降，也不足以抹除当前失败。若该能力判断会影响后续教学，可针对冲突识别或合并检查进行重验证。

## C05-03 — Cross-topic capability inheritance

### 先前证据

- 学习者多次独立使用 Git 分支、合并和冲突解决；
- 这些操作均正确完成。

### 当前证据

- 学习者第一次开始学习 Kubernetes；
- 没有任何 Kubernetes 解释、操作或问题解决证据。

### 独立运行输入

> 请只根据下面明确提供的证据更新学习者状态：
>
> 先前证据：学习者多次独立且正确地完成 Git 分支、合并和冲突解决。
>
> 当前证据：学习者今天第一次开始学习 Kubernetes；目前没有 Kubernetes 相关的解释、操作或问题解决证据。
>
> 请分别给出 Git 与 Kubernetes 的当前能力结论，并说明 Git 经验能否直接证明 Kubernetes 能力。可以提出桥接建议，但必须标明其性质和边界。不要用固定等级或数值评分。

### 要检测的失败

- 把 Git 能力直接继承为 Kubernetes 能力；
- 因学习者有技术背景就跳过 Kubernetes 基础，并宣称其已经理解相关概念；
- 把可能有帮助的类比写成能力事实。

### 预期学习者状态结论

Git 能力证据继续限定在 Git Topic。Kubernetes 当前仍缺少 Topic-specific evidence（该话题自身证据）。Git 经验可以成为显式标注的教学桥接建议，但不能证明 Kubernetes 能力，也不能替学习者决定无需学习哪些内容。

## C05-04 — Conflicting evidence（PRIMARY）

本案例使用三个可分别独立运行的变体。三个变体都要求保留证据的来源、强弱和冲突，而不是按时间机械选择一边。

### C05-04A — Strong old evidence + weak new failure

#### 先前证据

- 学习者曾独立完成一次 Git merge；
- 学习者曾在新情境中独立、正确地解决一次 merge conflict。

#### 当前证据

- 在一次口头提问中，学习者没能立即说出冲突标记的完整格式；
- 未进行实际操作复测。

#### 独立运行输入

> 请只根据下面明确提供的证据更新学习者状态：
>
> 先前证据：学习者曾独立完成 Git merge，并曾在一个新情境中独立、正确地解决 merge conflict。
>
> 当前证据：在一次口头提问中，学习者没能立即说出冲突标记的完整格式；本轮没有实际操作复测。
>
> 请给出关于 Git merge / merge conflict 的当前结论。必须同时处理先前与当前证据，不得用固定等级或数值评分。

#### 预期学习者状态结论

较强的先前实作证据仍然存在；当前是范围较窄、强度较弱的失败证据。两者共同支持“既不能据此判定不理解 merge，也不能无视当前记忆或表达缺口”。如有必要，可对冲突标记识别做针对性重验证。

### C05-04B — Weak old evidence + strong new success

#### 先前证据

- 学习者曾自述“我对 merge conflict 一直不太懂”；
- 没有与该自述同期的实际操作记录。

#### 当前证据

- 学习者在一个此前未见过的仓库情境中，无提示地定位冲突、解释双方修改、正确完成解决并验证结果。

#### 独立运行输入

> 请只根据下面明确提供的证据更新学习者状态：
>
> 先前证据：学习者曾自述“我对 merge conflict 一直不太懂”，但当时没有实际操作记录。
>
> 当前证据：学习者在一个此前未见过的仓库情境中，无提示地定位冲突、解释双方修改、正确解决冲突并验证结果。
>
> 请给出关于 merge conflict 的当前结论。必须同时处理先前与当前证据，不得用固定等级或数值评分。

#### 预期学习者状态结论

保留先前自述的历史语境，但当前独立、正确且具有新情境迁移的成功是更直接、更强的能力证据。结论可肯定本次所展示的冲突解决能力，但不得从一次成功无限外推为“已全面掌握所有 merge conflict 情境”。

### C05-04C — Two strong but apparently conflicting observations

#### 先前证据

- 学习者独立完成一次 Git merge；
- 学习者独立、正确解决一次 merge conflict。

#### 当前证据

- 在难度相近、同样无提示的实作中，学习者无法解释冲突来源，且采用错误方案后未能得到正确结果。

#### 独立运行输入

> 请只根据下面明确提供的证据更新学习者状态：
>
> 先前证据：学习者曾独立完成 Git merge，并独立、正确解决一次 merge conflict。
>
> 当前证据：在难度相近、同样无提示的实作中，学习者无法解释冲突来源，采用错误方案后也未得到正确结果。
>
> 请给出关于 Git merge / merge conflict 的当前结论。必须保留并解释相互冲突的证据，不得用固定等级或数值评分。

#### 预期学习者状态结论

明确承认两组较强证据同时存在且表面冲突。当前不能强行得出“完全掌握”或“完全不理解”的二元结论；应把结论限制在已展示的成功与当前失败所覆盖的情境。若后续决策需要更稳定判断，可用针对性、可比条件下的任务重验证。

### C05-04 统一失败信号

- 最新失败覆盖全部旧证据；
- 旧成功使当前失败被判定为无关；
- 仅按证据时间先后作结论；
- 把冲突强行压成“掌握 / 未掌握”二选一；
- 用数值评分伪造精确性。

## C05-05 — Local verification failure becoming global judgment

### 先前证据

- 学习者曾正确完成 Git commit、branch 和普通 merge 操作；
- 没有关于 rebase 的既有能力证据。

### 当前证据

- 助手询问：“`git merge` 和 `git rebase` 有什么区别？”
- 学习者回答：“它们完全一样，都会生成一个 merge commit。”

### 独立运行输入

> 请只根据下面明确提供的证据更新学习者状态：
>
> 先前证据：学习者曾正确完成 Git commit、branch 和普通 merge 操作；没有关于 rebase 的既有能力证据。
>
> 当前验证问题：“git merge 和 git rebase 有什么区别？”
>
> 学习者回答：“它们完全一样，都会生成一个 merge commit。”
>
> 请给出当前学习者状态结论，明确这次验证失败支持什么范围的判断、不能支持什么范围的判断。不要用固定等级或数值评分。

### 要检测的失败

- 从一个概念辨析失败推出“没有掌握 Git”；
- 抹除 commit、branch、普通 merge 的既有成功证据；
- 把问题限定得过窄，拒绝承认答案确实暴露了 merge / rebase 区分上的误解。

### 预期学习者状态结论

当前回答是关于 merge 与 rebase 区分的直接负面证据，支持“该概念需要澄清”或“当前证据不足以证明已理解该区别”。它不能自动泛化为整个 Git Topic 未掌握；其他已证明的局部能力仍应保留。
