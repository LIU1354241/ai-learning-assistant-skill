# AI 学习助手 Skill

[English](README.md) | **简体中文**

`ai-learning-assistant-skill` 是一份面向长期 AI 学习助手的稳定行为契约。它旨在帮助学习者了解自己当前所处的阶段、选择优先级、理解知识为什么重要、培养判断力，并与 AI 工具负责任地协作。

这个项目存在的原因在于：一个真正有学习帮助的助手，不应止于回答问题。一个正确的答案可以解决眼前的提问，却可能让学习者仍然不清楚该学什么、为什么值得学、下一步该如何判断。本 Skill 把这些反复出现的需求，转化为一套小而可执行的 Agent 规则。

## 从 i-have-adhd 中学到什么

本项目从 `i-have-adhd` 借鉴的是一种设计思路：从真实的人类摩擦与行为模式出发，再将其转译为 AI Agent 可以遵循的具体指引。它不复制该项目的内容，不假设每位学习者都有 ADHD，也不复现其具体实现。可复用的经验是这样一条路径：**人类需求 → 行为规则 → 边界 → 可测试的响应**。

## 与 OpenViking、Memory 和 Agent 的关系

- **Skill** 定义助手应如何推理和回应。
- **Agent**（例如 Codex、Kimi Code 或其他执行器）在这些规则之下完成任务。
- **Workflow** 负责任务步骤与检查的编排，但不重新定义学习者数据。
- **Memory** 可以提供持久的学习者上下文，但本 Skill 不存储数据。它只说明在用户同意的前提下，哪些稳定事实值得被记住。
- **OpenViking** 可以作为候选的上下文与记忆基础设施来探索。本仓库独立于它，也不强制与之集成。

这一设计让职责保持分离：行为属于 Skill，行动属于 Agent，步骤编排属于 Workflow，持久化属于一个有明确治理规则的 Memory 系统。

## v0.3 Stable

- 学习者匹配现在基于身份、目标、水平和阶段。
- 回复采用轻量默认结构加触发式模块，取代固定的长篇格式。
- 学习行为侧重于培养判断力，而不仅是传授知识。
- Skill、Memory 和 Workflow 保持各自独立的职责。

v0.3 保留八条核心规则、两种模式、明确的例外情况、一项自检和一条收敛的记忆策略。它不引入脚本、外部服务依赖、自动记忆，也不连接其他项目。
